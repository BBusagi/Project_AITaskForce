# AssetDesk 后续开发路径

v0.1.6 检索工程第一阶段：正式扫描与预扫描在同一次目录枚举中识别 Git／清单标记，移除逐目录重复探测；保护路径按进程缓存。SQLite 保存改为记录指纹比较与事务增量 UPSERT／删除，未变化记录不再重写；设置和单项标签通常只写一条记录。仍需序列化、比较全部内存对象，启动仍加载完整索引，尚无 SQL 分页／增量监听／MFT／USN。加入对照 v0.1.5 的隔离基准工具，S0／S1 部分完成；性能结果与限制见 [检索工程基准](performance-v0.1.6.md)。AI 保持冻结。

v0.1.4 当前调整：磁盘下拉框展开时自动刷新磁盘清单；原“刷新磁盘”按钮替换为“预扫描”。预扫描只读遍历同一排除规则下的文件／项目，统计当前可枚举数量，不创建资产、不写库；记录在本次会话内显示，重启不保留。支持暂停、取消、错误／排除计数；全电脑的注册应用／PATH 发现不计入估算。时间暂为枚举耗时 2–6 倍的未校准启发式区间，不保证覆盖 UI／合并／写库开销；取消或错误导致部分范围时不估算总耗时。正式扫描不设固定数量上限，仍受内存、存储、权限和排除规则限制，尚未证明百万资产性能。新扫描策略使旧达限缓存不再匹配，旧记录保留为历史。检索框仅在指定目录模式显示；全电脑／按磁盘模式隐藏并清空筛选。AI 保持冻结。

更新：2026-10-10；当前基线：v0.1.7。本文为未来计划，不代表功能已经实现；不承诺版本日期或未经测试的加速倍数。

## 当前边界

七项导航：总览、AI 分析、扫描与记录、应用清单、文件资产、个人化面板、设置。文件资产从独立导航或总览快捷入口访问，个人化面板目前展示项目与开发环境。

扫描、浏览、人工分类、应用视图、记录复制和 SQLite 持久化可用。扫描与分析缓存底层已实现，但扫描缓存只是历史快照，不检测磁盘变化。AI 页面保留结构、UI、配置和持久数据，预览、分析（包括缓存复用）、选择响应及接受／拒绝暂时冻结；未来重新设计后再启用。配置服务商与检查连接仍可用。

v0.1.3 曾限制每盘／目录 100,000 个资产；v0.1.4 已移除正式扫描默认限制。文件与项目都计入预扫描数量；旧达限快照不匹配新策略，历史记录不改变。

## 开发顺序与依赖

产品主线以 [产品方向与组织模型](product-direction.md) 为准：R0 定位与入口 → R1 应用用途分组／个人空间 → R2 待整理与持续维护 → R3 场景化 AI → R4 后置个人文件归档。

R0 文档与总览文案已交付，R1–R4 待开发。先交付无需 AI 的稳定组织规则；R2 持续发现依赖 S2；R3 依赖 R1 和 A0，AI 当前仍冻结。R4 是独立真实操作设计，不授权自动移动、删除或卸载。

检索工程 S0 → S1 → S2 → S3 继续推进，优先保障组织入口的查询响应、容量和持续发现。S0／S1 的单次枚举与增量写库已有局部实现，其余仍待开发。A0 可以与 R1 和检索工程并行设计；A2 依赖 S2，不直接启用旧标签界面替代组织模型。

以下 S／A 阶段是工程支撑，不能以更快的扫描代替查找、归位和维护体验的验收。

## S0：可复现性能基准（部分实现）

- 分别测量首次枚举、结果合并、入库、界面刷新、启动恢复和索引搜索，不将缓存命中速度当全盘扫描速度。
- 使用隔离的 10 万／100 万条目数据集，包含深层目录、项目密集、Unicode、排除范围与异常访问场景；真实磁盘测试由用户选择范围。
- 记录 OS、CPU、内存、SSD／HDD、文件系统、排除规则、冷／热状态、缓存命中情况。
- 输出耗时、吞吐、峰值内存、数据库体积、搜索 P95 与界面响应记录；以数据定位瓶颈，不预设加速倍数。

当前交付：`tools/AssetDesk.Benchmarks` 提供 1 万文件／10 万模拟资产对照，基线为 Git 提交 9a12067；百万条目、冷缓存及真实全盘基准仍待测。

验收：提供可重复执行的基准与基线报告，扫描／查询成本可分阶段解释，夹具扫描不改变源文件。

## S1：首次扫描与索引查询优化（部分实现）

- 增量维护资产身份查找表，避免每批重建全部资产字典。
- 将全库删除／重写改为有事务边界的批量增量 UPSERT；设置、标签与扫描批次独立提交，兼容旧数据库迁移。
- 引入可查询的结构化列与索引、分页查询、输入防抖，避免每次输入遍历全部资产或加载全部列表。
- 界面采用节流更新与列表虚拟化；扫描 → 有界队列 → 分批写库 → 增量 UI，队列满时施加背压。
- 一次枚举识别项目标记，预先计算保护路径；减少重复元数据调用与分配。
- 从低并发开始，以 SSD／HDD 基准调整并发和批次，提供取消、暂停与资源限制；不按目录无限创建任务。
- 先呈现基础元数据；用户常用目录可以优先，仍须明确剩余扫描范围。缩略图、哈希、内容分析按需加载。
- 包含匹配／中文搜索策略单独验证；普通索引不保证任意子串搜索加速，采用 FTS 等扩展前检查运行库支持。

验收：重复扫描保留人工决策；修改一项标签或设置不重写全部资产；查询按页加载；10 万／100 万基准公布前后指标与正确性结果。暂用式样书 AC-02／03／12 作为待验证预算，不宣称已达到。

资源管理目标：用户已要求解除固定数量上限，后续仍须验证内存、吞吐、取消与持久化，并设计有界队列与资源控制；遇到资源失败必须显示部分覆盖。扫描检查点与补扫策略须明确，不能仅提高数字或把反复全盘扫描当续扫。

已交付子项：同次枚举识别项目标记、保护路径缓存、指纹比较后增量写库。尚未交付：持续身份字典、结构化索引分页、UI 节流、有界管线与资源预算。

## S2：持续增量更新（待开发）

- 启动先展示已保存索引，并显示快照时间／待校验状态；后台更新变化，不每次重建全盘索引。
- 运行期间监听选定范围，合并短时间内重复事件并更新新增、修改、移动和删除候选。
- FileSystemWatcher 事件丢失或缓冲溢出时，将范围标为待校验并补扫；不把监听当唯一事实来源。
- 支持扫描检查点、正常重启恢复与变更游标；未能覆盖关闭期间的变化时明确提示并校验范围。
- 完整校验、稳定身份和覆盖证据足够时才确认消失；离线、权限失败或部分扫描不产生批量消失结论。
- 挂载卷身份、扫描策略或排除规则改变时使对应缓存／游标失效；更新源数据后保留人工标签并使受影响分析缓存失效。

验收：夹具的新增、修改、重命名、删除、关闭期间变化、断盘和事件溢出能恢复到正确索引；未变化范围不无故全量重扫，未校验状态始终可见。

## S3：可选 NTFS 快速索引（待开发，后置）

- 评估通过 Windows 官方 FSCTL_ENUM_USN_DATA 接口枚举 MFT 记录，再通过 FSCTL_READ_USN_JOURNAL 更新变更。
- 以卷身份、文件引用与父目录引用构建路径；处理多路径／硬链接、重命名、日志 ID 改变与日志保留窗口断档。
- 文件记录不是完整内容和应用清单；缺少的大小、时间等字段按需补充，注册应用与开发工具继续使用专用发现器。
- 不静默提权，不直接解析裸磁盘；所需卷访问权限在设计中明确。非 NTFS、权限不足或日志不可用时回退普通枚举并说明。

验收：支持范围内与普通枚举结果对照一致；日志断档可重建；回退不丢失限制提示；在相同基准上公布收益、资源和权限代价。

## A0：AI 分析功能重设计（已有协同分析草案，保持冻结）

新增 [本地证据与 AI 协同分析式样](local-analysis-design.md)：注册／结构化元数据关联 → 本地规则 → 有界分组摘要 → 疑难队列 → 有预算的 AI 提案 → 用户审核。单次 10 美元是可配置预算目标，不保证全部范围完成；证据关联、组缓存及预算引擎未实现，正文分析后置。

- 首批任务围绕下载资料归位、截图分类、项目资料关联、应用用途候选；提案需要对应类别或空间归属，采用后在日常入口体现。内容辨别和真实操作单独设计。
- 重新设计用户流程：选择目标和范围 → 预览将发送的数据 → 显示缓存／调用与用量估算 → 明确开始 → 查看证据与不确定项 → 用户逐项确认。
- 分析对象优先为有价值的文件、应用或项目摘要；不将全部系统文件／依赖逐个提交。采用项目级摘要时明确其覆盖与依赖来源。
- 明确本地规则与 LLM 分工、交互稿、输入／输出契约、空状态、错误、暂停／取消、审核历史与模型来源。
- 设计 token／费用预算与缓存可见性：估算和实际值分开，不将缓存次数直接等同累计金额。

验收：形成独立功能式样、流程与 UI 评审稿，确认范围和审核规则后才解除冻结；不直接启用旧交互代替重设计。

## A1：有限范围 AI 分析与审核（待开发，依赖 A0）

- 先在隔离夹具验证本地证据关联、分组摘要和未知状态。恢复 AI 前完成预算预留、实际用量结算及失败／重试记账；基础预算不能延后到 A2。

- 沿用服务商配置、DPAPI、有限元数据预览、本地契约验证与已验证结果缓存，适配新的界面与分析任务。
- 用户确认发送范围和目标服务；模型输出只形成分类／标签／分组提案，不带执行权限。默认不上传正文或完整路径。
- 显示来源、理由、未知项、缓存时间与本次调用状态；支持取消、失败重试预算、接受／拒绝及人工修正。
- 重复结果不重置审核、不重复添加提案；过期预览和建议不可采用。提示词／契约变更按版本失效缓存。

验收：隔离 mock 覆盖异常与缓存路径；用户选定的真实模型另行验证质量和权限。接受只修改索引，不改变保护状态或原文件。

## A2：变化范围分析与成本控制（待开发，依赖 A1 与 S2）

- 只重新分析语义受影响的对象／分组，保留未变化结果；分组依赖发生变化时重算受影响组，不盲目套用逐文件缓存。
- 显示本次范围、失效原因、缓存命中与实际服务返回的用量；设批次／token／费用预算，耗尽后暂停并让用户选择。
- 手动标签优先；身份不明、源数据过期或上下文不足时要求重新确认，不自动覆盖。

验收：改变一个对象只重算其依赖范围；组内关系变化正确失效；失败／取消不会提交未验证建议；预算和重复调用可解释。

## 保持后置的能力

正文／OCR、重复文件哈希、移动／删除／卸载、WSL／容器深度管理、恶意软件辨别不因上述路线自动进入开发范围。真实操作另行设计用户决策、对象复核、逐项结果与恢复限制。
