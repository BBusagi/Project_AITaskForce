# AssetDesk 产品方向与组织模型

更新：2026-10-10；当前客户端：v0.1.7。本文记录产品方向和后续功能要求，不将设计目标当作已实现能力。

## 1. 产品目标

为 Windows 提供统一的应用与个人资料组织方式：应用按用途浏览，资料有归属，新资料有待处理入口，常用内容易于返回。借鉴 iOS 的稳定入口和持续归类体验，但不模拟其文件系统或改变 Windows 的应用安装结构。

扫描数量与分类数量是技术指标；产品是否有效取决于用户查找、归位和持续维护所需的时间。

## 2. 三个主要组织入口

| 入口 | 目标行为 | 当前状态 |
| --- | --- | --- |
| 应用库 | 用途分组、系统组件显示控制、明确来源；优先展示用户常用应用 | 当前只有应用清单、列表／图标、系统相关开关和人工分类；用途分组与常用入口待开发 |
| 个人空间 | 工作、学习、生活、照片等可编辑空间；关联文件、应用与项目，保留原位置 | 当前个人化面板仅展示项目和开发环境；通用空间、成员关系和偏好待开发 |
| 待整理区 | 展示新增、归属不明和需要确认的个人资料；支持归入空间、暂缓、忽略 | 未实现；不能把所有系统文件或未知扩展名当作用户需要处理的资料 |

保持七项导航顺序。应用库后续在应用清单内演进；个人空间在个人化面板内演进；待整理区首先作为总览入口，详情通过文件资产或个人空间承接，不新增第八项导航。

文件资产保留完整元数据查看能力，是深入查找入口，不要求普通用户日常浏览整个目录树。程序员、设计师和普通用户共用资产模型，个人空间选择影响呈现，不产生三套独立扫描器。

## 3. 组织模型

- 资产记录保留来源、扫描时间、原位置与保护状态；缺失或过期信息明确显示。
- 空间是资产集合，一个对象可以属于多个空间，不能因此重复计算大小或重复创建资产。
- 类别说明对象用途，标签描述属性，空间表示用户归属；三者不能混为一列标签。
- 待整理是有依据的工作状态：新增待归位、用户标记待处理、归属不明候选。需要保存原因、首次发现时间、暂缓／忽略／已处理状态。
- 现有“未知”只表示规则未识别类别，不等同垃圾、可删除或待整理证据。
- 收藏／最近入口需要明确来源：用户收藏可以实现；扫描修改时间不能冒充用户最近使用时间。最近访问可先仅记录用户在 AssetDesk 内的访问，并如此标注。
- 系统和应用的数据目录不因为用户想整理就移动；安装位置与组件关联不能由 AI 任意重写。

## 4. 典型使用流程

第一次：选择希望管理的范围 → 获取索引 → 浏览应用或建立个人空间 → 将个人资料归入空间。

日常：打开个人空间或常用入口 → 找到应用／文件 → 处理少量待整理对象。

AI 后续流程：选择整理场景和范围 → 预览输入、目标服务和预算 → 接收可解释提案 → 确认或修正 → 更新空间归属／分类 → 在日常入口立即体现结果。

AI 第一批场景为下载资料归位、截图分类、项目资料关联和应用用途候选。优先分析个人资料／项目摘要，不将全盘所有依赖和系统文件逐条提交。用户修正可作为明确偏好保存，跨次使用时必须有来源、适用范围和失效规则。

AI 继续冻结，先完成任务式样与交互设计；不能用旧的批次标签界面直接代替新产品模型。

## 5. 界面组织与磁盘组织

第一阶段组织入口、集合关系和标签：不改变文件位置，也不假装已经整理了磁盘。

后续真正归档个人文件时，单独设计所选对象、源与目标、确认预览、对象复核、逐项执行结果、冲突处理和可恢复范围。用户对产品方向的认可不代表已经授权移动其实际文件。

系统目录整理、移动应用安装目录、自动卸载和删除不进入此阶段；旧索引、权限失败和 AI 推断不能直接形成删除指令。

## 6. 开发阶段

| 阶段 | 内容 | 状态／依赖 |
| --- | --- | --- |
| R0 | 产品定位、组织模型、入口与中性文案 | 本文和 v0.1.7 的总览／文案调整已交付；详细功能交互仍需补齐 |
| R1 | 应用用途分组、空间／成员模型、创建／编辑／归入空间、收藏 | 待开发；先形成稳定组织规则和 SQLite 迁移方案，AI 非前置条件 |
| R2 | 有依据的待整理状态、暂缓／忽略、增量维护 | 待开发；依赖 R1，持续发现依赖 S2，首批可基于明确扫描范围人工触发 |
| R3 | 场景化 AI 提案与用户偏好、提案影响真实界面归属 | 待开发；依赖 R1 和 A0；保留有限范围预览、本地验证、缓存和人工审核 |
| R4 | 所选个人文件的实际归档 | 后置独立设计；不能仅凭标签或空间变化就移动原文件 |

S0／S1 性能工程继续推进，优先服务这些入口的响应和可用规模；S2 保障新资料的持续发现；S3 为可选 NTFS 加速。速度改善不能代替组织模型的交付，更多文件条目也不能视为产品验收。

## 7. 产品验收方向

- 已知资料能通过空间、类别或搜索找到，应用能在用途分组中找到；记录任务完成时间与误选情况。
- 给定一批个人资料，用户能建立归属、暂缓或忽略，刷新／重启后决定保留。
- AI 提案采用后相应资料出现在正确空间，拒绝不会重复打扰或改写原有决定。
- 对新增、系统组件、未知和不可访问对象分别处理，不要求用户审核整个系统文件清单。
- 启动后能回到已建立的组织入口，不要求每次先全盘扫描。
- 扫描、查询与操作耗时独立记录；不以更快的枚举成绩替代查找和整理体验验证。

这些是未来验收方向，本次没有开展用户可用性测试。

## 8. 文案规则

界面使用功能名、对象、状态、来源和操作结果。移除口号、拟人承诺和重复的“由你决定”表述。权限或数据传输说明放在实际相关操作附近；不在侧栏、总览和每个页面反复堆叠。

未实现的功能不放置可操作的假入口，不把开发路线当日常页面文案。空状态提供具体可执行入口；示例数据明确标记，不代表发现了用户文件。
