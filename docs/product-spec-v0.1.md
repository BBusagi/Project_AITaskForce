# PC 资产管理工作台：式样书 v0.1

v0.1.6 检索工程第一阶段：正式扫描与预扫描在同一次目录枚举中识别 Git／清单标记，移除逐目录重复探测；保护路径按进程缓存。SQLite 保存改为记录指纹比较与事务增量 UPSERT／删除，未变化记录不再重写；设置和单项标签通常只写一条记录。仍需序列化、比较全部内存对象，启动仍加载完整索引，尚无 SQL 分页／增量监听／MFT／USN。加入对照 v0.1.5 的隔离基准工具，S0／S1 部分完成；性能结果与限制见 [检索工程基准](performance-v0.1.6.md)。AI 保持冻结。

v0.1.4 当前调整：磁盘下拉框展开时自动刷新磁盘清单；原“刷新磁盘”按钮替换为“预扫描”。预扫描只读遍历同一排除规则下的文件／项目，统计当前可枚举数量，不创建资产、不写库；记录在本次会话内显示，重启不保留。支持暂停、取消、错误／排除计数；全电脑的注册应用／PATH 发现不计入估算。时间暂为枚举耗时 2–6 倍的未校准启发式区间，不保证覆盖 UI／合并／写库开销；取消或错误导致部分范围时不估算总耗时。正式扫描不设固定数量上限，仍受内存、存储、权限和排除规则限制，尚未证明百万资产性能。新扫描策略使旧达限缓存不再匹配，旧记录保留为历史。检索框仅在指定目录模式显示；全电脑／按磁盘模式隐藏并清空筛选。AI 保持冻结。

当前 UI 阶段约束：侧栏依次为总览、AI 分析、扫描与记录、应用清单、文件资产、个人化面板、设置，文件资产独立导航位于应用清单与个人化面板之间，总览保留快捷入口。个人化面板目前沿用开发者内容。AI 整理助手功能等待重新设计，保留 UI 与持久数据但冻结交互、模型请求、缓存分析及审核；下文 AI 流程描述保留能力与后续目标，不代表本阶段可操作。扫描记录支持文本选中与复制；正式扫描无固定数量上限；旧达限记录仍为历史部分覆盖。

日期：2026-10-10；状态：v0.1.7 基线 + 后续目标（待开发）；范围：Windows 本地单用户 MVP。

工作名 AssetDesk。本文描述完整目标行为；已实现子集与验证限制见 [V0.1 实现状态](implementation-v0.1.md)，不能将式样书视为已全部实现。

## 1. 产品目标与范围

AssetDesk 为 Windows 提供应用与个人资料的组织层，让用户通过用途、空间和待整理状态查找与归位资料。扫描与 AI 为组织过程提供数据和建议，完整文件列表保留为深入查看入口。

组织模型与产品验收见 [产品方向与组织模型](product-direction.md)。当前 v0.1.7 仅实现扫描、索引浏览、人工分类和详情定位；应用库用途分组、通用个人空间、待整理区与收藏仍待开发。个人化面板现阶段仅展示项目和开发环境。

界面归类与磁盘整理分别交付：现有分类不改变文件位置。后续所选个人文件归档单独设计，不自动整理系统或应用安装目录。

## 2. 主流程

当前：恢复本地索引 → 从总览进入应用、文件或个人化面板 → 查看详情与人工分类；需要新数据时选择范围扫描。

目标：建立个人空间／用途分组 → 日常浏览常用资料 → 处理新增待整理对象 → 必要时请求 AI 提案 → 确认归属并在组织入口中体现。

AI 操作保持冻结。重设计需围绕下载资料归位、截图分类、项目资料关联等场景，不仅输出一批标签。持续发现依赖增量索引，不能把旧快照当实时状态。

扫描范围、排除与权限规则继续生效；不以“全电脑”声称完整覆盖全部账户或读取正文。

## 3. 信息分类

主资产域：

| 资产域 | 内容举例 | 默认管理行为 |
| --- | --- | --- |
| 系统组件 | OS、驱动、系统服务目录 | 只读展示、保护标记 |
| 应用程序 | 已安装应用、用户确认的便携应用 | 分类、收藏、打开系统应用设置 |
| 应用数据 | 配置、缓存、日志、共享数据 | 展示归属证据，不认定可清理 |
| 开发资产 | 工具链、项目、依赖、构建输出 | 独立面板、依赖保护、路径导航 |
| 个人文件 | 照片、截图、视频、音频、文档等 | 标签、筛选、收藏、定位 |
| 未知 | 缺少归属或用途依据的对象 | 保留未知、允许人工分类 |

资产域、内容类型与保护状态分别存储。应用关联或项目关联可以多对多；顶层占用统计采用唯一对象去重，未知空间不摊派给应用。

系统目录以系统 API 解析结果与显式规则标记，不仅靠路径名称。位于系统目录之外不代表安全可删。AppData 不整体归为缓存；Program Files 不整体归为 OS。

分类结果显示依据：例如“位于用户图片目录”“扩展名 .jpg”“命中已安装应用路径”。规则结果不得显示为模型概率；置信等级是可解释的证据等级。

用户覆盖优先于自动标签；重扫不覆盖用户设置。涉及系统／依赖的保护规则独立于用途标签，用户改分类不能解除保护。

## 4. 扫描式样

### SCAN-01 范围与权限

- 允许添加目录／磁盘、排除目录与文件模式；避免重叠根重复枚举。
- 默认当前用户权限；权限不足记录并继续，不改变 ACL。
- 顶部提供全电脑检索、按磁盘检索、已有指定目录入口。全电脑逐盘扫描本机已挂载固定／可移动磁盘，并发现卸载注册应用与 PATH 工具；磁盘模式只扫描所选磁盘。
- 不扫描网络盘、光盘或未挂载卷；未就绪卷记录为未扫描，权限不足不提权。全盘范围内其他用户目录是否可读依当前账户权限决定；不得伪称覆盖所有账户。
- 正式扫描不设固定数量上限；失败、取消与排除仍显示覆盖限制。逐范围保存结果；取消后尚未开始的磁盘记录为未扫描。
- OS 与应用受保护目录可以只显示路径与可获取的统计，不要求深入所有子目录。
- MVP 全盘元数据模式保留依赖目录条目及基本统计，但不逐文件展开 node_modules、.git 对象、虚拟环境、构建目录等默认排除子树；界面明确列出这些排除，不伪称完整覆盖。

### SCAN-02 层次与资源控制

- 基础层：路径、名称、扩展名、类型、逻辑大小、修改时间、属性、可访问状态。
- 定向解析层：受限读取项目清单和已知应用元数据，不读取一般文档正文。
- 深度层：后续版本的按需哈希、图像／文档内容分析，单独授权范围。
- 后台有界队列、分批写库、可配置并发；UI 不在主线程枚举目录。
- 超大单文件不读取内容；不可访问对象和扫描中消失的文件只产生局部错误。
- 目录连接、符号链接记录但默认不跟随；硬链接在能取得稳定文件身份时去重，否则标记统计为估计。
- 云端占位文件只读取可安全获取的属性，不通过缩略图、哈希或正文读取触发下载；无法确认时跳过并说明。
- 路径规范化不丢失原始显示路径；支持 Unicode、长路径与具有不同大小写语义的目录，不简单将全部路径转小写作为唯一身份。

### SCAN-03 状态与恢复

扫描状态：queued → running → completed／completed_with_errors；running 可进入 paused 或 cancelled；paused 可恢复 running；不可恢复的调度或存储故障进入 failed。

- 枚举完成前总数未知：显示发现／处理数量、当前范围、已耗时，不制造百分比。
- 暂停停止派发新批次；取消停止本次任务并保留已完成结果，标记为部分快照。
- 重启将中断任务标记 interrupted，允许从目录检查点重新枚举并去重，不承诺精确恢复到单文件位置。
- 完整成功扫过的范围才可判断旧条目已消失；部分失败、磁盘离线不产生批量删除标记。
- 索引查询可读扫描中的已提交批次；每个条目保存最近发现时间和扫描来源。
- 后续增量监听发生溢出时标记范围待重扫，不静默忽略丢失事件。

### SCAN-04 结果报告

展示所选范围、已完成范围、排除项、错误数量、离线卷、索引更新时间。用户可以定位失败目录并重新扫描。

### SCAN-05 扫描与分析缓存

- 检索默认复用扫描快照，匹配完整根路径、扫描策略版本／排除规则／上限和挂载卷身份。无法取得卷身份时不复用。显示旧快照时间和覆盖限制；用户勾选强制刷新才重新枚举。启动恢复索引不自动扫描。
- 正常完成、带局部错误或数量上限的快照可复用，保留其限制；取消／失败不替换可复用快照，原有旧快照仍保留。全电脑逐范围独立命中／刷新；应用环境发现使用独立快照，显式“刷新应用与环境”不使用旧缓存。
- AI 缓存键包含整批有序范围、整理目标、服务商／端点／模型、提示词与契约版本，以及已知名称／类型／大小／修改时间／版本／分类／标签／保护状态等指纹。只保存通过本地校验的结果；缓存命中不发模型请求、不消耗本次 API token。
- 接受／拒绝不能被重复缓存调用重置。接受导致标签变化时，仅为原本仍有效的范围绑定已审核结果；手动标签或其他元数据变化失效。过期预览不得发送，过期建议不得采用；强制重新分析会产生新调用。
- SQLite v3 独立缓存表，原有 v1／v2 原位升级；保存最近 200 批分析。设置可仅清缓存，保留资产、标签和审核记录；清空索引同时清缓存。
- 当前缓存不自动检查磁盘新变化，不保证内容身份追踪，也不跨模型或目标复用。整批分组可能依赖其他对象，一项变化会使整批失效。按变化项增量扫描／推理与费用遥测为后续工作。

空间字段分开显示“文件逻辑大小”“卷已用空间”“已索引合计”。稀疏文件、压缩、硬链接、共享目录、未扫描范围可能导致不同；不得称已索引合计等于真实可释放空间。

## 5. 应用管理

### APP-01 发现与分类

- 枚举机器／当前用户卸载注册信息，处理 32／64 位视图。
- 使用当前用户包清单补充 MSIX／Store 应用；权限或部署能力限制需报告。
- 开始菜单快捷方式与用户指定便携目录仅作为补充发现线索；发现 exe 不等于确定安装了一个应用。
- 按可靠标识合并来源；无法可靠合并则显示关联候选，不按名称盲目合并。
- 分类：开发、办公、浏览器、媒体、通信、游戏、系统工具、运行库／组件、其他、未知。内置用途规则可被用户覆盖。

### APP-02 详情

显示名称、版本、发布者、安装位置、发现来源、分类、最近扫描时间。缺失字段显示未知。

应用页支持列表／桌面图标视图，保持详情、Ctrl／Shift 多选和人工分类行为一致；AI 页面冻结期间不生成发送范围或提案。图标读取本地固定磁盘上的注册 DisplayIcon 资源（exe／dll／ico），不执行程序、不读取远程或离线占位资源；不可用时统一占位。保存视图与系统相关显示偏好。

“显示系统相关应用”默认开启；关闭仅过滤视图，不删除索引，被隐藏对象退出当前选择。系统相关依据为注册 SystemComponent=1、更新 ReleaseType 或 Windows 安装位置；不因微软发布者／Program Files 位置而认定系统组件。该标记独立于分类和保护状态，不能等同可删除性。旧记录需重新发现应用以补齐字段。

发布者来自安装元数据时明确标记，不宣称已验证签名。安装记录日期不等同于初次安装日期或最近使用时间。首版不提供缺乏证据的“长期未使用”标签。

大小区分“安装器报告大小”与“本工具已测量目录大小”。关联配置／缓存目录显示证据等级；共享目录不重复全部计入多个应用。

### APP-03 操作

可修改标签、收藏、打开安装位置、打开 Windows 应用设置。首版不执行卸载字符串、注册表修改或残留目录删除；卸载由系统设置或官方安装器完成。

## 6. 文件管理

### FILE-01 视图与搜索

提供图像、截图候选、视频、音频、文档、压缩包、安装包、源代码、其他分类。

支持名称、路径、类型、大小、修改时间、资产域、标签、关联项目过滤。首版为元数据搜索，不承诺全文搜索或图片内容搜索。

截图通过已知截图目录和命名规则生成候选标签，用户可修正；无法确认照片／截图的图像统一放入图像类。

### FILE-02 管理与重复项

首版操作为定位、复制路径、添加／移除标签、收藏。操作索引不等于删除磁盘文件；删除索引记录需明确措辞。

重复项留待 V0.2：先按大小筛选，再按用户选定范围完整哈希；相同哈希组仍需在执行操作前复核对象，硬链接作为同一内容对象处理。相同文件名不能作为重复证据。

## 7. 个人化面板（当前为开发者视图）

### DEV-01 开发环境

首批支持 Git、Node.js、Python、.NET。其他工具通过手动登记管理；版本管理器专用适配器、Java／Go／Rust、WSL／Docker 深度扫描后续扩展。

通过 PATH 位置、安装元数据、已知位置和项目清单形成发现候选；PATH 中的未知程序不自动执行。

版本优先读取可信文件／安装元数据；需要运行版本命令时使用已核实绝对路径、参数数组、超时、禁用交互和输出上限。不能保证无副作用的探测必须由用户单独启动，并明确将执行哪个程序。

显示工具类型、版本、位置、发现来源、探测状态、多版本列表、PATH 命中顺序。PATH 候选不等同于每个终端会话的实际默认版本。

多版本只是信息，不自动标为冲突。冲突提示至少给出证据，例如项目声明版本与所选运行时不符；未知版本不作兼容性结论。

### DEV-02 项目发现

- 用户指定项目根；依据 .git（目录或文件）、package.json、pyproject.toml、.sln／.csproj 等生成候选。
- 排除依赖目录内的清单，避免将每个依赖包当成用户项目。
- 同一目录可有多个技术栈；monorepo 采用项目根与子模块关系，嵌套独立仓库单独展示。
- 非 Git 项目仍可显示；检测标记不足时允许用户手动登记。
- 文件清单只作受限解析，限制大小和格式，不执行脚本、构建、安装或项目指定插件。

### DEV-03 Git 信息

验证工作树／裸仓库类型、Git 元数据位置，支持 worktree 的 .git 文件；首版裸仓库可作为仓库资产展示，不按工作目录处理。

在受控的只读适配器中取得分支、脏状态、最近提交和远程名称。状态探测禁用可配置的 fsmonitor 等外部执行路径，避免可选锁写入，限定参数并设超时；若无法证明只读与执行边界，首版仅展示已解析元数据并标记状态未探测。

不执行 fetch、pull、push、checkout、reset、clean、submodule update，不自动修改 safe.directory。可疑所有权仓库标记为不可探测。无提交仓库正常显示，缺少 Git 程序时保留候选识别结果。

远程 URL 展示和日志中去除用户名、口令和令牌。不得读取密钥文件或上传仓库内容。

### DEV-04 项目详情

显示名称、路径、技术栈、仓库类型、分支／未提交状态、最近提交时间、清单声明的环境要求及本机发现的匹配候选。

最近修改／提交不等于用户最近使用时间。项目大小区分已扫描大小与排除的依赖／构建目录。

首版提供定位项目与复制路径；从不自动运行 npm install、构建脚本或项目程序。

## 8. GUI 式样

采用全窗口桌面布局：左侧固定导航，中间列表／分类树，右侧详情或工作区；各区独立滚动。

当前导航与可操作范围如下；未实现的收藏、系统设置入口、环境登记、检查点恢复等保留为后续目标。

| 顺序 | 页面 | 当前信息与动作 |
| --- | --- | --- |
| 1 | 总览 | 数量／分类统计、示例资产；文件资产入口及人工分类 |
| 2 | AI 分析（AI 整理助手） | 结构、UI、历史建议保留；预览、分析、选择响应和审核冻结 |
| 3 | 扫描与记录 | 范围、状态、排除与错误；只读记录支持选择、Ctrl+A／Ctrl+C 与右键复制 |
| 4 | 应用清单 | 列表／图标视图、系统相关显示开关、详情和人工分类 |
| 5 | 文件资产 | 文件列表、元数据、详情、人工分类与标签、定位 |
| 6 | 个人化面板（开发者面板） | 项目标记与 PATH 环境候选、证据、位置和人工标签 |
| 7 | 设置 | 服务商、密钥、模型、连接检查、清缓存和清索引 |

顶部范围检索、强制刷新、应用与环境刷新、暂停／取消及全局搜索保留；正式扫描无固定数量上限；旧达限记录仍标记历史部分覆盖。

AI 设置采用服务商下拉框、掩码 API Key 输入框与“应用设置”按钮。支持 Ollama、OpenAI、DeepSeek、Anthropic / Claude、自定义 OpenAI 兼容；高级设置放置模型与地址。官方服务商固定官方地址，自定义使用 HTTPS。各服务商配置独立，密钥使用 Windows 当前用户 DPAPI 加密；留空保留旧值，可显式移除。应用配置不发送资产，连接检查不等同生成能力验证。

支持列表虚拟化、键盘导航、可读状态文本；颜色不能作为保护状态的唯一表达。

详情面板固定展示“原始位置、分类依据、保护状态、更新时间”。空状态引导扫描；部分扫描与扫描失败均显示已取得结果及覆盖限制。

扫描期间页内显示状态条，不用阻塞弹窗。概览应回答“我电脑里有什么”；开发者页面应回答“项目在哪里、有哪些工具、版本有什么依据”。

## 9. 数据式样与服务边界

SQLite 为建议持久化；不要求 HTTP 后端。

| 实体 | 核心字段 |
| --- | --- |
| ScanJob | id、范围、状态、检查点、计数、时间、规则版本 |
| ScanIssue | job_id、路径／范围、错误类别、可重试状态 |
| Volume | 标识、挂载点、文件系统、在线状态 |
| FileEntry | id、volume_id、稳定身份（可选）、路径、类型、大小、属性、发现时间 |
| Application | id、来源键、名称、版本、发布者、安装路径、大小来源 |
| DevelopmentTool | id、工具类型、版本、路径、来源、探测状态 |
| Project | id、根路径、技术栈、仓库类型、Git 摘要、更新时间 |
| AssetRelation | 端点、关系类型、证据、等级、规则版本 |
| Classification | asset_id、维度、标签、自动／人工来源、依据 |
| UserPreference | 模式、范围、排除项、界面偏好、资源限额 |

对象缺失、离线、不可访问、未知是不同状态。身份无法稳定确认的重命名不应承诺跟踪成功；用户标签需要关联失败提示与人工重连入口。

内部服务：StartScan／PauseScan／ResumeScan／CancelScan、QueryAssets（分页）、GetAssetDetails、SetUserTags、RefreshScope、RegisterProject、ClearIndex。

事件：ScanStateChanged、ScanProgress、AssetBatchCommitted、ScanIssueDetected、ClassificationChanged。事件只用于更新 UI，数据库快照是可恢复状态的依据。

每个扫描器返回来源、证据、覆盖范围和局部错误，不只返回一份“完整清单”。数据库需 schema_version 和迁移策略，扫描任务与批次有事务边界。

## 10. 安全与隐私要求

- 首版无文件写操作、无自动卸载、无静默提权；应用自身的数据库与日志可正常写入。
- 启动或清空索引不会删除用户文件；清空提示区分索引、标签和原始文件。
- 不主动读取浏览器凭据、.env、SSH 私钥等敏感文件内容；日志避免完整私密路径和远程凭据，调试导出由用户明确选择。
- 不自动启动发现的 exe、打开 Office 宏或执行项目脚本。
- 默认离线可用；不包含广告、不上传目录树、不默认发送遥测。
- 后续真实操作必须独立设计：保护规则、目标身份复核、锁定／权限／磁盘空间检查、预览、逐项结果和恢复限制。跨卷移动、卸载与删除不能承诺通用一键撤销。
- LLM 只能读取用户确认范围内的信息，不能绕过操作审批与本地验证。
- 首版支持本机与用户配置的云端 LLM：用户确认有限范围的元数据及目标服务商；名称和标签是不可信数据；使用结构化输出与本地严格校验。密钥仅用于对应服务认证，不放入模型输入或错误正文；关闭重定向与代理。模型结果不得携带文件执行命令，接受只更新索引。内容分析留待后续单独设计。

## 11. 验收标准（目标与当前状态）

以下是完整目标，其中性能、自动恢复、用户包与高级 Git 等尚未交付；当前 AI 相关验收用于未来重新启用阶段。v0.1.3 已验证七项导航、冻结 AI、记录文本选中与应用视图；详见实现状态。以下不是已测性能。基准环境记录 OS、CPU、内存、磁盘、文件数量与扫描规则。

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 首次扫描 | 用户能选择根与排除项，扫描后原始文件内容和结构未被修改 |
| AC-02 | 扫描中交互 | 参考机：4 核、16 GB 内存、本地 SSD，10 万文件夹具；列表操作目标 P95 < 200 ms；扫描与 UI 独立 |
| AC-03 | 资源控制 | 同一基准下索引阶段内存目标 < 500 MB；取消／暂停目标 2 秒内停止派发；阻塞 I/O 单独记录 |
| AC-04 | 异常对象 | 拒绝访问、断盘、长路径、符号链接循环、文件消失不导致整个应用崩溃 |
| AC-05 | 扫描覆盖 | 已知可访问且未排除的夹具文件全部入库；失败和排除范围均可查看 |
| AC-06 | 应用发现 | 自建 Win32／用户包夹具正确显示；便携候选和缺失字段不伪装为确定事实 |
| AC-07 | 开发环境 | 四类支持工具夹具发现路径与证据；多版本展示；未知程序不自动运行 |
| AC-08 | 项目与 Git | 普通、无提交、worktree、非 Git、嵌套仓库正确区分；依赖包不生成大量伪项目 |
| AC-09 | 分类与统计 | 人工标签重扫后保留；交叉分类不重复计入顶层合计；未知可见 |
| AC-10 | 持久化 | 重启恢复已提交资产与标签；中断扫描可重新枚举；部分失败不误标全范围消失 |
| AC-11 | 数据与执行边界 | 扫描无网络传输；AI 仅发送用户预览确认的有限元数据；不发送完整路径／正文；不修改被扫描对象或执行仓库配置程序 |
| AC-12 | 搜索 | 基准数据下分页元数据查询目标 P95 < 300 ms；名称、类型、路径和标签结果可验证 |

全盘扫描耗时不规定通用保证：规模、磁盘、排除项和权限影响过大。技术验证需测量 10 万与 100 万条目的时间、吞吐、数据库体积及资源消耗，再确定正式性能预算。

## 12. 待确认事项

下列不阻碍文档评审，但在实施前需确认：

1. 是否只做 Windows；本草案按 Windows 优先规划。
2. 首批用户是否以开发者为主；本草案采用开发者优先、普通模式可用。

5. 是否要识别广告／恶意软件；若需要，必须单独评估安全产品能力与证据来源。

Windows／Git 技术依据与链接集中列于项目评估；本文中权限、扫描和执行边界为产品设计要求。
