# 本地证据与 AI 协同分析式样（A0 草案）

更新：2026-10-10。本文是未来设计，未实现分析引擎，不解除 AI 冻结。10 美元为可配置的单次任务预算目标，不保证全部范围完成；时间和费用收益需测试。

## 流程

索引快照 → 本地证据关联 → 规则判断 → 项目／文件组摘要 → 疑难对象队列 → 数据预览与预算 → 有限 AI 提案 → 本地验证 → 用户审核。

本地引擎识别对象类型、项目／应用关系和证据缺口；AI 提出有歧义的用途和空间候选。结果分为扫描事实、本地规则候选、AI 候选和用户决定，不将推断写成事实。文件类型、用途、归属和保护分别记录，用户标签或模型建议不能降低保护。

“内部信息”首批指已有索引关系、按需本地版本资源和项目清单白名单字段。正文、图片内容、OCR 和文档嵌入元数据分别后置设计；本方案不默认读取或上传正文。

## 本地证据与规则

| 来源 | 有限证据 | 判断边界 |
| --- | --- | --- |
| 资产索引 | 类型、扩展名、大小、时间、扫描范围和保护 | 旧快照不是实时状态；修改时间不是使用时间 |
| 应用注册信息 | 名称、发布者、版本、注册安装位置 | 注册信息可能过期；不能证明目录内所有文件都属于应用 |
| 项目标记／清单 | 项目根、语言／框架／依赖名称等白名单字段 | 只读解析，限制字节、嵌套和项数；不执行脚本、加载插件或联网补全 |
| 本地版本资源 | 产品名、发布者、版本 | 自声明字段不是可信性证明或安装事实，失败时保留未知 |
| 用户决定 | 类别、标签、空间归属、明确设置的适用规则 | 人工决定优先；一次修改不自动推广到其他目录 |

每条证据保存来源、身份、采集时间、有效范围、版本和冲突。路径仅用于本地关联，规范化后验证卷身份和目录边界，不使用字符串前缀判定归属。明确重解析点、网络路径和离线占位处理策略，不能为获取证据执行程序或隐式下载云端文件。

先判定文件类型，再形成项目／应用关联候选，最后判定整理用途。嵌套项目优先最近有效根，允许多种关系；应用目录包含关系只支持候选，不能作为所有权定论。名称、目录名、时间聚集为弱线索。人工决定保留，新冲突单独提示。

等级采用“明确来源支持／多线索支持／弱线索／未知”，初期不把分数显示成准确率。规则保存适用维度、命中证据与版本；冲突、过期、部分覆盖或解析失败进入待确认状态，后续用标注夹具校准。

## 分组与摘要

按关系和用户目标建立项目组、应用组、资料目录组或文件模式组。同目录或同扩展名不能单独证明用途相同；混杂组细分或保留未知。嵌套组不重复统计，身份不明及硬链接的计数限制明确说明。

摘要使用请求内短编号，包含类型／版本、数量、类型分布、覆盖状态、证据类型、少量代表性名称和未知／冲突计数。完整路径、注册表值、Git 远程地址、邮箱、密钥和完整依赖清单默认不发送。示例名称仍可能敏感，必须可预览和排除。

按类型／规则状态分层选取有界样本，记录样本数、选择方法及未查看数量。基于已有索引分批聚合，按需补充和缓存证据，避免反复全盘扫描、重读正文或无界内存。

组建议先作用于组的用途／空间候选。推广到成员需列明规则、成员、例外和未检查对象，经用户审核；抽样不等于逐文件检查。困难成员可单独分析。

## 模型请求与结果

按用户目标相关性、未解决／冲突程度、可减少的审核工作量和预计成本排列疑难队列。系统／应用内部对象默认保留本地证据，无需逐项提交；未提交不能标为已完成 AI 分析，证据不足可以保持未知。

请求仅包含有限摘要和对象，输出受限类别／空间编号、必要标签、简短组理由、例外编号和未知状态。请求中的编号映射回本地身份；类别／空间版本固定。越界、重复、无效编号、截断 JSON 和过期指纹不可采用。

名称、清单及样本是不可信数据，不能改变指令或授予文件权限。模型没有扫描、移动、删除、卸载或脚本执行能力。用户预览并明确开始，验证通过的候选由用户接受、拒绝或修改。

## 预算和缓存

单次任务预算目标默认 10 美元，可配置；主要分析约 7 美元，其余用于细分和重试，比例可调整。主要节省来自减少云端决策对象，不承诺仅压缩 JSON 就能完成近两百万条逐项分析。

发送前按序列化请求与模型分词估算输入，以已知单价和最大可计费输出预留费用，包含思考 token、适用附加费用、估算误差和并发在途额度。价格／分词／用量不能可靠确定时不宣称严格美元上限；硬预算模式停止未知费用路由。

开始请求时原子预留，完成后按返回的实际用量结算；无用量、超时和取消不能直接退回全部额度，需保守记账或核对账单。重试重新占用额度。预算不足即停止发起请求，保留待处理队列；区分已分析、缓存复用、本地判断、等待预算、未分析和失败。记录调用数与用量，不保存凭据或原始敏感请求正文。

组缓存键包含身份、成员依赖及字段指纹、覆盖状态、规则／摘要／采样版本、任务目标、相关用户偏好、类别／空间版本、服务路由与模型／契约版本。成员、清单或相关决定改变时仅失效依赖范围；人工审核单独保存，失效不能重置用户决定。

现有实现为 1–40 项整批分析和最多保留 200 条批次缓存，尚无上述组缓存、预算引擎及任务续跑。依赖感知批处理与显式刷新可先做；自动持续变化分析依赖 S2，快照复用不是监听。

## 开发与验收

1. A0：完善证据、规则维度、摘要、模型契约、预算记账和审核交互；本文仍是草案，保持 AI 冻结。
2. A1 前置：隔离夹具实现本地关联／摘要原型，先输出本地报告，不读取用户正文、不调用模型；比较逐项基线的请求字节／token 估算、耗时和峰值内存。
3. A1：范围预览、验证、预算和审核完成后恢复新流程；基础预算是首次启用条件，不延后到 A2。
4. A2：持久化组依赖缓存、变化范围重算与持续更新；自动变化发现依赖 S2。

夹具覆盖陈旧注册信息、相似路径前缀、嵌套项目、混杂目录、恶意／超大清单、部分覆盖、采样遗漏、人工修正、缓存失效、错误响应、并发额度、超时和重试。分别测类型、项目／应用关联及用途候选质量，不把样本覆盖率或模型自评分当准确率。

真实模型验证需公布同范围下的云端对象数、输入／输出 token、账单、总耗时、未知／冲突比例和人工审核量。未测前不宣称节省比例；HTTP mock 只能验证契约及预算路径。预算耗尽明确未完成范围，不强行填充分类或伪装全部完成。
